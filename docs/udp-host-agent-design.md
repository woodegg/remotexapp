## 1. 问题与目标 / Problem and goals

一台宿主可能运行多个容器，每个容器又有多个显示实例，每个显示实例可被多个
Viewer/Tab 同时访问。逐个手工配置公网端口、容器代理和端口归属，会把容器的
创建、停止、删除、重建和迁移都变成运维操作。

目标是：部署方为宿主配置一次策略，之后由容器声明发布需求，宿主自动验证、
分配、建立、续租、恢复和回收。容器不需要知道 Incus/LXD 命令、宿主防火墙规则
或其他容器的网络信息。重复请求和故障恢复必须收敛到同一有效状态。

当前 [UDP 契约与端口池实现](https://github.com/woodegg/remotexapp/blob/5dd1e079f576110441db2063fa02e0054ed918b3/docs/native-udp-uat.md)
是对照基线：部署方预配置不重叠的静态槽位，Manager 在自己的清单内分配。
本文提出将跨容器的分配权集中到每台宿主的单一权威服务。原有静态模式继续保留；
该变更只有在实现、故障测试和迁移验收后才可取代它。

## 2. 职责与边界 / Ownership

| 组件 | 负责内容 | 权限边界 |
| --- | --- | --- |
| 容器内 Manager | 声明自身显示组件需求、确认监听就绪、续租和释放、报告可用性 | 保持非 root；不持有宿主 Incus/LXD 凭据或管理 socket |
| 宿主代理 Host Agent | 自动发现、调用方识别、全局分配、持久化租约、协调和配额 | 只管理部署策略授权的容器和自己拥有的网络对象 |
| 转发后端 Forwarding backend | 双向 UDP 转发、实际对象状态和清理证据 | 首阶段使用现有 non-NAT 代理；后阶段评估 ICE 单端口分流 |
| 部署方 Deployment owner | 安装服务、容器模板、入口/防火墙/公网地址、资源限额和升级 | 云安全组与宿主权限留在部署项目，不交给工作负载 |
| 可信边缘 Trusted edge | 浏览器身份入口、固定资源、信令与头部地址过滤 | 容器内应用不能替换这层可信资源或扩大授权 |

控制面（Control plane）传递发布意图和租约；数据面（Data plane）传递实际 UDP。
WSS 继续承担控制、输入、剪贴板和完整画面回退。新增 Host Agent 不接管 App
启动/停止、自恢复预算、HOME、shutdown veto 或音频。
现有 Viewer grant 仍由 Manager 签发、续租与撤销；Host Agent 的发布租约
不替代浏览器授权，可信边缘也不取得跨运行实例签发 grant 的权力。

Host Agent 是新的宿主信任组件。实现应将需要宿主权限的容器查询、网络命名空间
访问和代理变更收敛到小型适配层；请求不能携带任意命令、宿主路径或目标地址。
具体进程拆分及最小权限方式在实现前审阅，不能把拥有宿主 API 的进程描述为无特权。

## 3. 一次配置与自动发现 / Bootstrap and discovery

部署方一次性配置宿主标识、公网 advertised address、允许端口池、可接入容器的
策略、每容器/宿主配额、转发后端、认证方式及日志策略。公网入口由部署信息提供，
支持宿主处于上游地址映射后的情况；容器不自行猜测公网 IP。

容器模板启用接入标记及受限注册通道。Host Agent 在启动时列举允许的容器，监听
生命周期事件，并定期核对实际清单，处理事件丢失或断线。容器新增和正常重建不再
要求人工为每个显示编辑宿主 proxy。普通未启用容器不获得注册通道。

首选同宿主专用 Unix socket：部署层把受限端点暴露给对应容器，宿主结合端点归属、
调用进程的宿主可见凭据和容器命名空间确认身份。不能只依赖请求中的容器名、来源
IP 或 UID；不同容器的 UID 映射可能重叠。凭据和状态不能随镜像克隆给另一个实例。
容器名复用、克隆和重建都必须得到新的实例身份版本（incarnation）。

Incus 的 Guest API 提供宿主识别调用容器的设计参考，但它不是现成的 UDP 发布
API；不得假设可以向 `/dev/incus/sock` 写入本提案消息。Incus 与 LXD 的适配分别
实现和验证。跨主机控制通道可后续采用短期身份和 mTLS（双向 TLS），首阶段不依赖
服务发现集群或证书平台。

## 4. 登记对象与租约 / Publication and lease

一个 publication 表示一个显示组件的 UDP 发布关系；同显示的多个 Viewer 共用它。
每个 Viewer 仍保有独立的 ICE/DTLS、授权、会话代际和连接 epoch。

| 字段组 | 拟议内容与来源 |
| --- | --- |
| 宿主身份 | host identity、host boot identity，由宿主生成/核验 |
| 容器身份 | 不可混淆的实例标识、incarnation、当前网络命名空间归属，由宿主确认 |
| 显示归属 | Manager identity、runtime ID、display incarnation、锁定组件身份 |
| 发布请求 | 协议版本、幂等请求 ID、服务类型、受策略限制的内部监听需求 |
| 宿主租约 | publication ID、lease ID、lease epoch、revision、expiry、期望/实际状态 |
| 转发配置 | 后端类型、公网入口、经宿主解析的容器内目标、受管对象归属标签 |
| Viewer 路由 | 可选复用后端另记录授权的 ICE 标识、session generation、Viewer/connection epoch 和到期信息 |

publication 的资源租约与 Viewer 授权、App keepalive lease 是三个独立对象。
持久显示保留时，session generation 更新可以撤销旧 Viewer 而不重新分配显示端口。
网络租约续租、STUN、转发流量和健康检查都不能给 App 续命或反向启动已停止 App。

宿主只允许调用方登记自身策略范围内的显示目标，按容器和整机限制 publication、
请求速率、转发状态、缓冲和带宽。阶段 A 的 Viewer 授权数量由 Manager 限制；
不能用代理数量代替 Viewer 数量。阶段 B 的复用后端另限制已登记 Viewer 路由与
握手状态。拒绝其他容器地址、任意宿主服务和未知
类型。内部目标须通过宿主已核验的命名空间访问，不能把宿主自己的 loopback 当成
容器 loopback。使用现有代理或专用命名空间适配器；容器不能传入 namespace 路径。

## 5. 拟议交互 / Proposed protocol

采用版本化请求/响应；下表是语义约定，HTTP 路径、编码和错误码仍需实现评审。

| 操作 | 语义 |
| --- | --- |
| PreparePublication | 验证身份/策略，原子保留资源并持久化；相同请求与意图返回原租约，内容冲突明确拒绝 |
| ActivatePublication | Manager 确认组件绑定成功后，核验归属并建立代理；实际就绪后才返回可用于协商的入口 |
| RenewPublication | 使用当前 owner、lease epoch 和 revision 续租；过期租约、旧请求或旧 incarnation 不能复活 |
| ReleasePublication | 幂等撤销指定版本的发布；先禁用新流量/路由，再清理旧映射，确认后释放槽位 |
| ReconcilePublications | 比对该调用方完整、带版本的期望集合与实际状态；分页/中断快照不能触发误删除 |

正常流程：发现容器 → 准备并保留入口 → 启动/核验 Kasm 内部监听 → 激活代理 →
返回就绪入口 → 发起 Viewer 协商 → 续租或释放。准备失败或超时要回收已保留资源；
不可把“配置提交成功”当作实际可用，更不能当作 Viewer 已收到画面。

宿主是本机入口分配的单一权威；所有容器共享原子分配器。只允许一个活动分配者，
或使用经过验证的等价排他机制。写入归属后才变更外部对象，崩溃恢复按记录与实际
对象核对。端口探测不等于独占，绑定失败必须回滚或隔离，禁止覆盖其他服务。

首阶段保留当前相同内外端口约束。宿主选端口后，Manager 尝试绑定对应容器内部
端口；冲突则拒绝该次激活并有界重试。普通租约续租和 Manager 重启保持分配。
同一命名空间若存在多个 Manager，部署身份和局部端口分配也必须隔离。

租约期限、续租间隔、最大撤销时间、准备超时和恢复预算在 PoC 前锁定为测试参数；
文档不虚构已经量测的数字。期限使用宿主权威时间；同一启动期间使用单调时钟。
跨宿主重启不能直接重用单调时间，必须重新核验并重新授权。

## 6. 自动恢复与清理 / Reconciliation and fencing

| 场景 | 必须达到的行为 |
| --- | --- |
| 并发创建、请求重试、响应丢失 | 原子唯一归属；请求可重放且结果幂等；资源数量不持续增长 |
| Manager 短暂失联 | 有效期内保留已核验发布；重新确认当前归属后续租，旧实例请求被拒绝 |
| 租约到期 | 拒绝续租复活，停止新流量并清理旧发布；需新申请才能重新建立 |
| 容器正常停止或删除 | 事件触发撤销，周期核对兜底；仅清理本服务拥有的代理 |
| 同名重建或克隆 | 新 incarnation；旧凭据、旧发布和旧 Viewer 不能关联新容器 |
| Agent 崩溃或重启 | 核验持久记录、容器 incarnation 和真实代理对象；确认后恢复或隔离，不盲目重放 |
| 宿主重启 | 重新发现、重新核验/授权；旧 boot identity 下的迟到消息不能重新激活资源 |
| 代理创建/删除或持久化失败 | 显式 degraded/quarantined 状态，保留不确定槽位，限制重试并允许 WSS |
| 容器迁移 | 旧宿主撤销后新宿主申请；首阶段不承诺 UDP 无缝迁移，重协商或 WSS 回退 |
| Agent/代理升级 | 版本兼容检查、明确排空与撤销；记录可能断连及现有 App vacancy 策略 |

资源状态至少区分 reserved、active、retiring、quarantined、released。
只有确认旧转发、旧连接映射和旧归属清理完成后才可复用入口；迟到响应不能覆盖新
lease epoch。容器隔离、租约清理都不能通过杀死未知 App 进程实现。

Agent 自身死亡后不能依靠它继续执行删除。实现评审必须选择并验证宿主监督/独立
到期执行机制，证明最长撤销与回收期限。现有 Incus proxy 不提供本提案的租约到期
语义，不能假定 Agent 退出后 proxy 自动消失。Viewer 授权到期仍独立执行；残留代理
不代表继续授权，但其资源必须隔离到确认清理。无法保证的故障范围明确标记未支持。

已有 UAT 的入口切换曾使 Viewer 断开并触发 App vacancy 清理。新网络服务保留
原有 App 生命周期，不以网络续租阻止回收，也不承诺保留一个旧 listener 就能无缝
切换。实现需验证业务持有引用、重连和用户提示，避免把网络故障误判为用户关闭。

## 7. 两个转发阶段 / Forwarding backends

**阶段 A：自动管理多端口代理。** 复用已验证的 non-NAT 转发原则，由 Host Agent
在宿主端口池内管理代理；云安全组提前开放受限范围。解决跨容器自动登记、冲突、
回收和恢复。Manager 不直接写宿主配置；后续容器不需要单独人工配置公网端口。

**阶段 B：单公网端口复用 PoC。** 保持同一登记/租约抽象，增加识别 ICE/STUN 的
数据面，将多个显示/容器的流量分到独立内部目标。需要额外登记当前 Viewer 协商，
不能仅靠每显示的一条 publication 判断所有数据包的目标。

ICE ufrag 用作路由线索，不能充当授权。路由只能来自已授权信令，初始握手验证和
后续绑定要有界；普通加密数据包不都带 ufrag。必须验证同源并发、相同 NAT、源
tuple 冲突/变化、ICE restart、旧包和晚到响应。不能确认归属时拒绝/回退，禁止
仅按客户端 IP 或随机负载均衡把数据送入另一个显示。

优先研究透明转发并保留浏览器到 Kasm 的 DTLS 边界。若必须终止 DTLS/DataChannel，
需作为新的信任和协议设计单独审阅。Pion 的单端口示例只是实现参考，不证明现有
多个独立 Kasm 进程可直接共享它，亦不承诺 Kasm/SDK 无需修改。

公网只暴露一个端口时，内部仍可有独立端口和代理连接，容量仍受 CPU、内存、
带宽和状态配额限制。阶段 A 的验收不代表阶段 B 已支持。

## 8. 原始地址隐藏与观测 / Privacy and diagnostics

继续使用代理创建的后端连接、禁用 PROXY protocol，并保留容器外可信信令/HTTP
地址过滤。容器内工作负载只看到代理侧地址；宿主知道原始客户端地址。不得把原始
地址通过注册响应、状态、日志、指标或 token claim 重新传给容器。
保证范围仍是受信浏览器到指定隔离工作负载的路径，不扩展为任意应用流量的匿名性。

向 Manager/SDK 返回 publication 状态、后端类型、到期/恢复状态和固定错误原因，
例如 quota-exceeded、host-unavailable、binding-conflict、lease-expired、ownership-unknown。
UDP ready 仍须有真实数据和画面证据。记录内容无关的事件、重试次数、租约/代理数量、
队列和资源；不记录凭据、原始 SDP、用户输入或远程文档。

## 9. 兼容、部署与回退 / Compatibility and rollout

静态 catalog 模式与自动模式显式区分，不能同时管理同一端口。自动模式在能力协商
和版本检查通过后启用；协议不匹配时使用 WSS，并报告原因。网络状态的 schema、
能力及 Host Agent 版本必须纳入锁定产物；旧 Manager 不得猜测新租约状态。

迁移按显示组件范围进行：保留数据与旧配置，停止/排空旧转发并确认资源清理后，
交由新所有者管理。不得在运行中静默把静态归属改成租约归属。回退先撤销自动发布，
确认无残留再恢复静态配置；应用数据和已有明确的停止意图始终保留。

本仓库可实现和验证组件，并向部署项目交付版本化服务、协议、配置模板和回退说明。
宿主服务安装、模板接入、云安全组、启用与实际升级由目标部署项目负责。本文写入
不触发当前 UAT 的服务重启、网络修改或发布。

## 11. 分期范围与实现前置条件 / Delivery slices and prerequisites

已批准的架构方向是阶段 A 的自动多端口管理；首个真实适配目标选择 Linux/Incus。
LXD 单独适配与验收，阶段 B 不进入本轮实现。为将协议错误与宿主操作分开定位，
按以下检查点推进；这是工程实施顺序，不表示后续检查点已验收。

| 检查点 | 交付与验证边界 |
| --- | --- |
| A1：协议与租约状态机 | 定义版本化消息、身份/代际/幂等/错误语义；在身份、时钟、持久化和转发接口后实现状态机与原子分配器，用临时存储和模拟后端测试并发、失败及恢复。不接入当前 Manager 或修改宿主代理。见 [#44](https://github.com/woodegg/remotexapp/issues/44) |
| A2：真实宿主边界实验 | 验证 Incus 容器 incarnation、专属 socket 引导和命名空间目标识别，以及 Agent 死亡后的独立到期执行。先选定最小权限适配方式，再启用真实发布 |
| A3：产品集成与验收 | 接入 Manager、发现/协调和代理；在专用环境执行第 10 节多容器、真实浏览器、故障/reboot、隐私、资源和迁移回退矩阵 |

A1 必须显式区分“模拟身份已验证”与“真实容器身份已证明”，以及“控制器重启后
可以恢复”与“控制器死亡期间仍能按期撤销”。模拟测试不能替代 A2 的证明。
持久化失败、转发状态不确定或旧资源清理未确认时，保留隔离状态而不复用槽位。

在真实接入前仍需锁定：发行/维护归属和权限适配层；身份与 socket 注入方式；
具体协议/schema；租约期限、独立到期执行和恢复预算；quota/容量门槛；灰度与
回退步骤。数字需作为实验参数明确记录，不能把未测参数称为生产容量或故障承诺。
阶段 B 的协议分流、tuple 冲突处理和是否修改 Kasm 由独立 PoC 决定。
Issue/PR 保存进度和批准，本文保存技术契约；现有静态端口模式仍是运行基线。
