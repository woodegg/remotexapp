# P18: native Viewer retirement

Repeated native Viewer release left detached canvas/input trees retained by
BroadcastChannel callbacks and global Window listeners. SDK owner counters
returned to zero, so the initial functional harness passed while resource
review failed. The selected client patch closes owned channels, removes global
listeners and clears pending gesture/resize timers. Native server binaries and
libraries remain bit-identical to the verified parent component.

The [results](results.json) retain the original resource samples and failed
channels-only attempt. The [manifest](manifest.json) binds the result, patch and
current harness. Compare within-run deltas; the page's warm-up node count differs
between the diagnostic probes. The baseline and both twenty-cycle probes use
Core source `6c5e5309a947`; final qualification uses `89697ec59743` and the new
component. The harness gained resource assertions and another twenty-cycle
block after resource review found that owner counts alone were insufficient.

Every cycle requires real paint before release. After warm-up and each block,
diagnostic GC precedes DOM/listener/heap sampling. One explicit background task
retains the App; there are zero Views/canvases and idle audio. Logout then releases
that last owner. Final DOM/listener values are 97/26 at all three samples; heap
is 1.732, 2.318 and 2.376 MiB. No forced-GC policy is added to ordinary clients.
This demonstrates removal of the identified retention roots, without proving
long-duration heap, CPU, PSS/RSS or arbitrary workload behavior.

The full native regression separately passes input/readback, clipboard, synthetic
audio, reconnect and UDP checks on the final pair. Owned test Apps/browsers are
closed and fault containers stopped. The original non-test Manager/display
identities remain unchanged; project-owned local UAT retains the qualified pair.
This is development acceptance of the resource repair, not human UAT or release.


## 2026-11-27 follow-up: detached native input (#115)

The earlier P18 measurements retain their original channel/global-listener
scope. A later real Chrome 158 repeated-Host run found another non-weak root:
the document animation controller holds a detached keyboard textarea, whose
adapter-owned blur listener retains its constructor's RFB lexical context.
Three Viewers per owner retained about 16.73 MiB of ArrayBuffer backing stores
after owner 1, 434.79 MiB after owner 26 and 836.14 MiB after owner 50; the
eighty-second live idle retains that last value. Bounded Worker/audio counts do not
qualify those display buffers. This observation is not a long-term slope or
whole-browser RSS/PSS claim.

The adapter now saves/removes its own blur callback before input removal.
A deterministic held-input test fails on the old adapter and passes on the new
one, preserving live blur cancellation and unrelated listeners. Real new-component
resource controls are recorded below; exact post-merge archive, human and release
qualification remain separate in #115/#106. Existing runtime pins
must not be modified; select a rebuilt immutable component with verified
unchanged server provenance. Raw heaps and deployment identities remain
outside Git.


An independent actual-Chrome source mechanism control retains 51 distinct
native input nodes deliberately, using the actual adapter/input/gate/latency
modules and a stub RFB with a 4 MiB buffer. The old adapter retains 51 RFBs and
204 MiB; the new adapter retains zero RFBs/backing-store bytes. This isolates
the callback root, not a real server or new-component performance result. The
initial minimal control accidentally retained the keeper input repeatedly;
its observation is rejected. The selected control asserts distinct inputs.


The current recovery-cycle harness now includes a positive live RFB/backing
store snapshot and requires zero retired RFB owners plus less than 4 MiB of
backing stores before and after both twenty-cycle blocks. It streams snapshot
chunks independently of bounded CDP event history, saves raw heaps privately
with mode 0600, and reports counts/digests. The manifest retains the historical
harness hash; the original P18 results were not generated by this later guard.


The reconstructed component control on the same Core passes the enhanced public
forty-cycle harness: live RFB positive count 1, then retired count 0 and 3200
backing-store bytes before/after both blocks; DOM/listeners stay at 156/20.
A separate supplied Chrome 158 control uses three Viewers and two actual audio
routes across fifty owners, then 80 seconds live idle. All five retired
endpoints have zero RFBs and 6400 backing-store bytes; live controls see three
RFBs. Audio Context/Worklet/Proxy end at 0/0/0, native Worker/port stay at the
permitted document bootstrap 1/1, and owned Apps/context are cleaned. Actual
served client hashes match the new component manifest. These controls isolate
the fixed input root; they are not a new natural hour, whole-browser RSS/PSS,
physical-device, immutable post-merge Core or human UAT result.
