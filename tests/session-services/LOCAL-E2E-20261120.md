# Local managed-session fix qualification

Issue [#65](https://github.com/woodegg/remotexapp/issues/65), PR
[#66](https://github.com/woodegg/remotexapp/pull/66), measured 2026-11-20.
This extends the [observation-failure regression](README.md#session-liveness-observation-fault)
to the packaged product and local native host. It is development integration
evidence, not post-merge release qualification or renewed human UAT acceptance.

[Machine-readable evidence](../evidence/v1/managed-session-local-e2e-20261120.json)
records the overall fault campaign as failed because lease-outage recovery
fails. It preserves the individually passing liveness/functional checks and
binds the raw-evidence and test-source hashes.

The tested archive was built from clean source
`c947fddf0cc94017c2f3bfc097ed77338026c781` with Go 1.27.4:
`remotexapp-0.16.0-linux-amd64.tar.gz`, SHA-256
`6bd8fb69bbe7c0cc62d8b8a96065102b44a69fcbe84663d65bfb82ef2bd77e4d`.
Its development deployment uses a separate PR-specific installation directory;
the archive is not a replacement for the published 0.16.0 release. Subsequent
test/documentation changes do not change the tested binaries.

## Environment and deployment boundary

Tests use Ubuntu AMD64, systemd, real TigerVNC and the existing pinned Kasm
component, Node 22.22.3, and isolated headless Chrome 149.0.7827.102. The broad
fault suites run in new project-owned containers or locked disposable accounts.
Local deployment preserves the existing non-test Manager and display process
identities. No sandbox or regional deployment is part of this experiment.

The existing local native UAT was upgraded separately from fault injection.
Its trusted edge initially retained older SDK assets; the edge was restaged
with the matching product assets, all 13 directly served asset hashes were
verified, and its actual browser workflow and channel suites were rerun through
a temporary loopback test connector. That connector was closed afterward.
This exercises the trusted edge locally, not Cloudflare Access or public TLS.

## Failed automatic-recovery gate

**This local run does not establish complete automatic self-recovery.** The
`lease-outage` browser gate fails reproducibly: HTTP connectivity is blocked
across the next 20-second grant renewal, then restored; the Viewer remains
failed with `grant-expired` instead of automatically reconnecting. The lease
catch handles every failure identically, including transient network errors
before the 90-second expiry. The SDK code is unchanged from the main baseline;
this is a newly demonstrated existing defect, not a liveness-fix regression.

[Issue #68](https://github.com/woodegg/remotexapp/issues/68) records the root
cause, reproducible command and acceptance criteria. A repair must obtain a
fresh authenticated grant through bounded reconnect while continuing to reject
real authorization loss/revocation and stale generations. The failed gate stays
failed; separate Manager and short-outage passes do not override it.

See the [fault/recovery matrix](FAULT-RECOVERY-MATRIX.md) for input-helper,
borrowed-bus and gateway cases that preserve the App but still require explicit
recovery. Do not present those preservation passes as automatic repair.

## Harness corrections and retained attempts

- The headless browser's default 780-pixel width selected the compact layout,
  which hides the ownership panel. A background-task release click therefore
  hit empty space. The desktop workflow now sets its viewport before testing
  desktop controls, and the common click helper rejects hidden, disabled or
  obscured controls. The explicit mobile layout check remains.
- The managed-entry probe needs a running App, not merely a ready display.
  Its setup now waits for the real application status after attaching the seed
  Viewer. The passing lifecycle/reboot/rollback suites were retained, and the
  entry probe was rerun after satisfying this precondition.
- Direct LXC output redirection lost the first legacy suite's log. The complete
  exact-archive bundle was rerun with ordinary pipes and retained output.
- The old broad matrix expected supervisor death to kill every App, including
  user-home XFCE. The existing `ExitType=cgroup` protection intentionally keeps
  a live desktop alive; it is present in the baseline too. The user-home rows
  now assert dead-supervisor identity, surviving canonical App/services,
  unchanged generation, real full frames, Manager adoption and explicit-stop
  cleanup, with a separately runnable `supervisor-preservation` gate. The
  private-bus App failure/cleanup assertions remain unchanged.
- Shutdown fault checks previously treated the enforcement start deadline as
  a completion deadline. XFCE needs the separate systemd 10-second stop timeout.
  The harness now retains the original persisted `forceAt`, checks completion
  within 15 seconds after it, and requires the final forced flag and unchanged
  deadline. This measures bounded completion, not an exact internal start time.
  Both the original timeout and an intermediate overly strict flag-polling
  attempt are retained; no product timeout was changed.
- Chrome REPL evaluation returned an unresolved async-expression Promise as
  `{}` despite `awaitPromise`. The shared CDP helper now keeps the remote handle,
  awaits Promise results explicitly, serializes values and releases the handle.
  A real-browser regression covers top-level await, async expressions, ordinary
  values and rejection. The complete private-Pulse browser audio suite passes
  with the corrected helper; native host suites use a different non-REPL helper.
- The runit clone contained a pre-release native component that could not send
  the required Viewer grant; the Manager correctly rejected its handshake.
  The fixture now uses the same qualified component as the native host tests.
  Old-component attempts remain failures and are not called compatible passes.
- Additional private fixture setup attempts exposed root-owned unit drop-ins,
  the default five-minute safety interval, rejection of loopback UDP endpoint
  addresses, the local `ws-loopback` label, and explicit rejection of enabling
  UDP without a reserved slot. These were corrected in fixture setup/assertions;
  no product validation, timeout or safety boundary was weakened.

Raw attempts, synthetic documents, process identities and deployment backups
remain private. Public evidence must bind the completed gates and cleanup to
the archive hash rather than treating a running process as a passing test.

## Remaining acceptance boundaries

Physical Windows/macOS IMEs, physical speaker/microphone quality, public
Cloudflare/TLS/NAT paths, fresh Alpine/ARM64 qualification and a new long-duration
soak are outside this local run. Earlier results for those environments do not
qualify this artifact automatically. Merge, human acceptance and publication
remain distinct steps.

## Final cleanup

All eight matrix runs' temporary accounts, UID processes and HOME directories
were verified absent. The two owned fault containers were stopped after their
App/Viewer counts reached zero. Owned Chrome profiles and loopback connectors
were closed; temporary UDP proxies/address/Manager override were removed.
The normal local legacy and native UAT services remain running on the tested
archive with zero test Apps/Viewers. All 13 served edge asset hashes match.
The original non-test Manager and display process identities remain unchanged.
